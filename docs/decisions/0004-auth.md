# 0004 — better-auth instead of a hosted identity provider

**Status:** accepted · 2026-09-11

## Context

Accounts are needed for multi-device access, but requiring Auth0/Clerk/Supabase Auth would make self-hosting depend on a third party.

## Decision

better-auth with the Drizzle adapter, storing users/sessions/accounts in our own Postgres. Email+password by default; GitHub OAuth when keys are present; password reset by SMTP or, without SMTP, a logged link.

## Consequences

- Zero external services for a single-user install.
- The auth tables follow better-auth's column naming; `lib/auth/index.ts` is the only file that knows about the library, so swapping it later is contained.
- A guest/local-only mode is not implemented; the architecture allows it (a fixed local user) but it's not wired.
