# Self-hosting

GameSettings Vault is a single Next.js server plus a PostgreSQL database. Nothing else is required.

## Option A — Docker Compose (recommended)

```bash
cp .env.example .env
# Set at least:
#   BETTER_AUTH_SECRET   openssl rand -base64 32
#   BETTER_AUTH_URL      https://vault.example.com   (the public URL, no trailing slash)
#   NEXT_PUBLIC_APP_URL  same as above
docker compose --profile app up -d --build
```

This starts Postgres (`db`) and the app (`app`) on port 3000. Migrations run automatically at boot (`RUN_MIGRATIONS=true` in `docker-compose.yml`). Put a reverse proxy (Caddy, nginx, Traefik) in front for TLS.

Data lives in the `gsv-pgdata` volume. Back it up with `pg_dump`:

```bash
docker compose exec db pg_dump -U gsv gsv > backup.sql
```

## Option B — Node on a host

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm db:migrate
PORT=3000 node .next/standalone/server.js
```

`next.config.ts` uses `output: "standalone"`, so `.next/standalone` contains everything the server needs (copy `.next/static` and `public` next to it, as the Dockerfile does).

## Environment variables

| Variable               | Required | Notes                                                                                             |
| ---------------------- | -------- | ------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`         | yes      | `postgres://user:pass@host:5432/db`                                                               |
| `BETTER_AUTH_SECRET`   | yes      | ≥16 chars; signs session cookies. Changing it signs everyone out.                                 |
| `BETTER_AUTH_URL`      | yes      | Public origin of the app. Used for CSRF/origin checks and email links.                            |
| `NEXT_PUBLIC_APP_URL`  | yes      | Same value; available to the browser bundle.                                                      |
| `GITHUB_CLIENT_ID`     | no       | Enables "Continue with GitHub". Callback: `<URL>/api/auth/callback/github`                        |
| `GITHUB_CLIENT_SECRET` | no       |                                                                                                   |
| `SMTP_URL`             | no       | `smtp://user:pass@host:587`. Without it, password-reset links are printed to the server log.      |
| `EMAIL_FROM`           | no       | Sender for transactional mail.                                                                    |
| `RUN_MIGRATIONS`       | no       | `true` → apply `drizzle/*.sql` on startup (the Docker image sets this).                           |
| `AI_VISION_PROVIDER`   | no       | Reserved for the optional screenshot assistant. See [ai-providers](architecture/ai-providers.md). |

`lib/env.ts` validates these at startup and fails with a readable message if something is missing.

## Database

- Migrations are plain SQL in `drizzle/`, generated by Drizzle Kit from `lib/db/schema.ts`.
- Apply them with `pnpm db:migrate` (or `RUN_MIGRATIONS=true`). They are idempotent.
- Any Postgres 14+ works; the compose file ships 16.

## Email

Password reset is the only email the app sends. Any SMTP provider works. When `SMTP_URL` is unset the reset link is logged instead, so a single-user install never needs email.

## Updating

```bash
git pull
docker compose --profile app up -d --build   # migrations run at boot
```

## Optional services

| Service       | Purpose              | Default      |
| ------------- | -------------------- | ------------ |
| GitHub OAuth  | Social sign-in       | off          |
| SMTP          | Password-reset email | off (logged) |
| AI vision API | Screenshot assistant | off          |

There is no telemetry and no analytics.
